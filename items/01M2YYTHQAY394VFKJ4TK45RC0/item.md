## Scope

Two of `decisions/DEC-005-alpha-scope.md`'s remaining alpha bullets. First,
`docs/spec/domains/audio.md`: register all 64 `SoundEvent`s (one per catalogue line, generated from
`VV-3`'s catalogue, never hand-typed, `AUDIO-REQ-001`), their `sounds.json` entries, and their
`subtitles.villager_voices.reaction.<event>.<n>` lang keys, each backed by a valid near-silent
placeholder `.ogg` carrying the line's real subtitle text (`AUDIO-DEC-001`, `AUDIO-REQ-002`). Play
server-side via `ServerLevel.playSeededSound(..., SoundSource.NEUTRAL, ...)`
(`audio.md` §3 "Playing server-side"). Second, `docs/spec/contracts/data-contract.md`: the one
config file (cooldowns, category mutes, display toggles, queue timing — `DATA-REQ-002`), format
TBD at this ticket, wiring `VV-2`'s hardcoded cooldown defaults and `VV-7`'s hardcoded display
defaults to operator-overridable values.

## Approach

A generator (build-time or a small annotation-free loop over `VV-3`'s catalogue at mod init) that
registers `Registry.register(BuiltInRegistries.SOUND_EVENT, id, SoundEvent.createVariableRangeEvent(id))`
for all 64 ids, writes the matching `sounds.json` entries and lang strings, and resolves each
catalogue line's now-real broadcast radius back into `VV-7`'s hearing-range check
(`DISPLAY-REQ-002`). Generate every line's placeholder `.ogg`: a genuine mono OGG Vorbis file,
~0.1–0.3s near-zero amplitude, never empty or missing (`audio.md` §3 "The near-silent placeholder").
Config: one file in the server's config folder, JSON5/TOML per the loader's own convention (format
choice recorded in Findings), degrading to shipped defaults on a malformed file rather than
crashing or corrupting anything (`DATA-REQ-004`), carrying an internal schema version from 1.0
(`data-contract.md` "Versioning").

## Acceptance criteria

- [x] All 64 `SoundEvent`s registered, one `sounds.json` entry and one lang key each, generated from
      `VV-3`'s catalogue, never hand-typed (`AUDIO-REQ-001`).
- [x] Every line's `.ogg` is a valid, playable file that is genuinely present (`AUDIO-REQ-002`); a
      catalogue line with no matching `.ogg` fails the build naming the missing line id
      (`AUDIO-FAIL-001`).
- [x] Vanilla subtitles appear for a placeholder sound with "Show Subtitles" on, with zero custom
      HUD code (`display.md` §3 "Subtitle layer").
- [x] The config file's cooldowns/mutes/display toggles/queue timing round-trip correctly and a
      malformed file falls back to defaults without crashing (`DATA-REQ-002`, `DATA-REQ-004`).
- [x] `AUDIO-REQ-005`: nothing in this ticket makes a network call of any kind — placeholder
      generation is a build-time-only step, never invoked at runtime.

## Constraints and prior findings

Blocked by `VV-3` (the catalogue this generates registrations from). Real Piper-generated audio
(`VV-11`) replaces these `.ogg` files "file-for-file... no registration, code, or catalogue-format
change" (`AUDIO-REQ-003`) — do not design the registration path around eventually swapping it, it
already satisfies that requirement by construction. `AUDIO-REQ-006`'s reproducibility (seeded
generation) applies to `VV-11`'s real Piper batch, not this ticket's placeholder generator, which
has no voice model to seed.

## Findings

- **Audio tool**: `ffmpeg`'s bundled Vorbis encoder only emits stereo, so the placeholder was built
  in two steps — `ffmpeg -f lavfi -i "sine=frequency=600:duration=0.2:sample_rate=22050" -af
  "volume=0.015" -ac 1 -c:a pcm_s16le placeholder.wav`, then `oggenc -q 2 -o placeholder.ogg
  placeholder.wav` (`vorbis-tools`, installed via `brew install vorbis-tools` — not present on the
  machine beforehand). Result: genuine mono OGG Vorbis, 22050 Hz, 0.2s, mean volume -57.6 dB / peak
  -54.3 dB (near-silent, not true digital silence, per `audio.md` §3).
- **One shared placeholder file, not 64**: `sounds.json`'s 64 entries all name
  `assets/villager_voices/sounds/reaction/placeholder.ogg` — confirmed `sounds.json` permits the
  same file under many sound ids. Keeps the jar small per this ticket's own brief. Generated by a
  one-off Python script reading the 16 shipped catalogue JSON files (never hand-typed), cross-checked
  by a fabric unit test (`SoundsJsonResourcesTest`) that `sounds.json`'s 64 keys equal the
  catalogue's 64 sound ids exactly. **Caveat for `VV-11`**: swapping in 64 real per-line `.ogg`
  files means editing `sounds.json`'s 64 `"sounds"` arrays too (one path each, instead of the
  shared placeholder) — still no registration, code, or catalogue-format change, so `AUDIO-REQ-003`
  holds by its literal wording, but it is not a pure drop-in-the-files replacement the way a
  1:1-named-from-day-one layout would have been. Worth a decision note at `VV-11` if that ticket
  wants the stricter "bytes only" version of the requirement.
- **`sounds.json`'s actual path**: the ticket brief said `fabric/src/main/resources/sounds.json`;
  the real Minecraft asset convention (and what the game actually loads) is
  `fabric/src/main/resources/assets/villager_voices/sounds.json`, matching where
  `assets/villager_voices/lang/en_us.json` already lives. Filed there, not at the resources root.
- **Config format**: JSON (`ConfigCodec` on top of `MiniJson`, no new dependency), one file,
  `config/villager_voices.json` in the game's config directory, written with defaults on first
  server start and read back on every server start (`ConfigLoader`, `DATA-REQ-002`). Nested shape:
  top-level `schemaVersion` ("1.0"), `cooldowns.{perVillagerPerEvent,perVillagerGlobal,
  serverRatePerPlayer}`, `display.{actionBar,subtitleHint,queueMinHoldTicks,masterVolume,
  hearingRangeBlocks}`, `categories.{trade,combat,social,raid}.muted`. `Config`'s compact
  constructor clamps any out-of-range value to its own shipped default, so a `Config` instance can
  never be invalid regardless of how it was built (`DATA-REQ-004`); a malformed file is left
  untouched on disk (never auto-rewritten) and the session falls back to defaults.
- **Not yet behaviourally wired, though present and round-tripped in `Config`**:
  `categoryMutes` (no filtering hook exists in `VillagerEventBus`/`ReactionRules` without adding
  new selection logic beyond "use the existing constructor parameters", which this ticket's brief
  explicitly scoped out) and `display.subtitleHint` (subtitles are entirely client-side/automatic
  once a sound plays; there is no per-player server-side lever to suppress them selectively without
  routing sound packets per-player instead of via `ServerLevel.playSeededSound`'s broadcast). Both
  are genuine follow-up work, most naturally alongside whichever ticket first needs them
  (event-category filtering probably belongs with VV-4/5/6's own territory).
- **`display.hearingRangeBlocks`**: not in `docs/spec/domains/display.md` §3's config table today —
  added because this ticket's own brief named "hearing range" as a required `Config` field, and
  because `DISPLAY-REQ-002`'s eventual "the line's own sound event's effective broadcast radius" is
  not wired anywhere yet (VV-7's `ActionBarDisplay.PLACEHOLDER_HEARING_RADIUS_BLOCKS` is the same
  kind of stand-in). Defaults to the same 16 blocks. Worth folding into `display.md`'s table once a
  ticket actually reads a real per-sound radius instead of a flat config override.
- **`VillagerEventBus` gained a fifth constructor overload** (`..., ReactionRules rules)`), purely
  additive — the four-argument constructor now delegates to it with `new ReactionRules()`. Used to
  plumb `Config`'s cooldowns into the bus without touching `ReactionRules`' own logic.
- **`FabricLineCatalogue`** (new, `fabric/.../catalogue/`) adapts VV-3's `Catalogue` (string-keyed)
  to VV-2's `LineCatalogue` (`VillagerReactionEvent`-keyed) — both packages' own Javadoc anticipated
  exactly this piece of glue but neither had written it yet.
- **Server lifecycle**: `SoundRegistration.registerAll()` and the `CatalogueReloadListener`
  registration stay at mod init (`onInitialize`, required for registry-mutation timing); the config
  load, the config-sized `DisplayQueue`, the config-sized `ReactionRules`, the real
  `VillagerEventBus`, and every `VillagerEventSource#register` call now happen in a
  `ServerLifecycleEvents.SERVER_STARTED` callback instead. A world restart within one client session
  (leave a singleplayer world, load another) re-fires `SERVER_STARTED` and rebuilds all of that,
  including re-running `source.register(bus)` for every discovered source — harmless today since
  `FabricVillagerEventSource.register` is still a no-op, but VV-4/5/6's own event-hook registrations
  should either be idempotent-safe against a repeat call or unregister on `SERVER_STOPPING` once
  they exist.
- **`javap`-confirmed 26.2 signature** used for playback:
  `ServerLevel.playSeededSound(Entity, double, double, double, Holder<SoundEvent>, SoundSource,
  float, float, long)`, entity `null` (pure position broadcast, per `audio.md` §3). Volume
  0.4 base × `display.masterVolume`, `SoundSource.NEUTRAL`, pitch 1.0.
- Fixed `SourceSurfaceTest` (VV-3/earlier), which read every file under `src/main/resources` as
  UTF-8 text: the new binary `.ogg` placeholder broke it (`MalformedInputException`). Now skips
  `.ogg`/`.png`/`.jar` before the reference-product text scan.
